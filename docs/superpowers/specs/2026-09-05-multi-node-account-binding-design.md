# 账号多节点代理绑定设计

## 目标

在账号管理页的“账号-代理配置”对话框中支持一次选择多个兼容代理节点，并把当前选中的账号均衡分配到这些节点。系统自动计算每个节点的建议绑定数量和可编辑上限，管理员确认后复用现有绑定接口完成绑定。

## 约束

- Build、Web、Console 使用同一套前端分配逻辑。
- 节点仍由现有作用域规则筛选：Build 只显示 Build 节点，Web 只显示 Web 节点，Console 保留现有 Console/Web 兼容节点。
- 每个账号最终只能绑定一个节点，后端数据模型和现有单节点绑定接口不变。
- 不修改 Provider 请求、额度、认证、数据库结构或自动均衡逻辑。
- 不把代理地址、Cookie 或其他敏感内容加入新接口或新状态。

## 交互

1. 管理员先在账号表格中选择一个或多个账号，再打开“绑定代理”。
2. 对话框列出当前 Provider 可用且已配置代理的节点；节点显示名称、已绑定数量和容量，并支持多选。
3. 选择节点后显示“每节点绑定数量”数字输入框。
4. 默认值为 `ceil(选中账号数 / 选中节点数)`，但不超过自动计算的最大值。
5. 最大值为所有选中节点剩余容量之和除以节点数后向下取整。容量为 `0` 的节点视为不限容量，但在计算时最多按当前选中账号数计入，避免出现无意义的无限值。
6. 管理员可以把输入值调小或调大，但不能超过最大值；没有可用容量时禁用绑定。
7. 点击绑定后，按节点列表顺序轮询分配账号，每个节点最多接收输入值且不超过自己的实际剩余容量。已分配账号按节点分组，依次调用现有 `POST /api/admin/v1/egress-nodes/:nodeId/accounts` 接口。
8. 某次调用失败时停止后续调用，刷新账号和节点数据，并提示已完成数量和未完成数量，避免无提示的部分绑定。
9. 解绑保持现有行为不变。

## 分配算法

对每个节点计算：

```text
remaining = accountCapacity > 0
  ? max(0, accountCapacity - assignedAccountCount)
  : selectedAccountCount
```

然后：

```text
maxPerNode = floor(sum(remaining) / selectedNodeCount)
defaultPerNode = min(maxPerNode, max(1, ceil(selectedAccountCount / selectedNodeCount)))
```

实际分配使用轮询游标。每轮选择下一个仍有剩余容量且未达到 `perNodeLimit` 的节点；如果所有节点都不能再接收账号，则停止并把剩余账号作为未分配结果。

## 错误与一致性

- 节点加载失败、没有兼容节点、输入为空或没有可用容量时，绑定按钮保持禁用并显示原因。
- 输入值在提交前再次规范化，防止浏览器状态或旧缓存绕过上限。
- 复用现有 API 的逐节点提交，不新增后端批量协议；部分成功时通过结果提示和数据刷新让管理员可见。
- 成功或部分失败后清空账号选择，防止重复点击造成误绑定。

## 测试

- 纯函数测试默认值、平均上限、有限容量、不限容量、节点容量不足、账号数少于节点数和输入超限。
- 前端构建、lint、现有测试必须通过。
- 后端不改业务代码，仅运行现有 Go 全量测试确认接口兼容。
- 线上用临时管理员创建的客户端 Key 分别调用 Build、Web、Console 模型，确认部署后服务正常；临时 Key 测试结束后删除。
